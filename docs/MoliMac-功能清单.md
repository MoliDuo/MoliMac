# MoliMac 功能清单（待你逐条 Review）

> 调研日期：2026-10-04
> 目标：把 **DockDoor**（Dock 预览 + 窗口切换）、**Mac Mouse Fix**（鼠标）、**状态栏收纳**（Bartender / Ice 一类）合成一个应用 **MoliMac**。
> 同类工具里好用的功能也一并列出。

## 怎么 Review

每条功能都有编号。「建议」列是我的初步判断，「决定」列留给你填：

| 标记 | 含义 |
|---|---|
| ✅ | 要 |
| ❌ | 不要 |
| ⏳ | 以后再说 |
| ❓ | 需要再聊 |

**我的优先级建议：**

| 标记 | 含义 |
|---|---|
| 🔴 P0 | 刚需，第一版就要有。没有它 MoliMac 就不成立 |
| 🟠 P1 | 重要，第一版最好有 |
| 🟡 P2 | 锦上添花，第二阶段 |
| ⚪ P3 | 建议砍掉或很后面再做（小众、成本高、或别的 App 做得更好） |
| ❓ | 取决于你的使用习惯，需要你拍板 |

**来源缩写：**

## 0. 先拍板的几件大事（会影响后面所有功能）

| 编号 | 问题 | 背景 | 我的建议 | 决定 |
|---|---|---|---|---|
| D-01 | **最低支持哪个 macOS？** | 1. **macOS 27（2026 年 9 月发布）把状态栏架构彻底改了**：所有图标都画在 MenuBarAgent 进程的一个窗口里，旧的收纳方法全部失效，Ice 至今不能用。在 27 上只能「按 App 整体隐藏」（用私有的考试模式白名单 API），**不能再用程序重新排序或点击图标**。<br>2. Liquid Glass 外观需要 26 及以上。<br>3. 系统自带的「关闭指针加速」需要 14 及以上。 | 如果只是自用，**只支持你自己在用的版本**（大概率是 26 或 27），工作量能少一半。<br>如果要发布，最低支持 14，状态栏需要写「≤26」和「27」两套引擎。 | |
| D-02 | **开源还是闭源 / 收费？** | 1. DockDoor、AltTab、Ice、Thaw 都是 **GPL-3.0**，借用它们的代码，MoliMac 也必须开源成 GPL。<br>2. Mac Mouse Fix 3 用的是自定义「MMF License」，**不允许衍生品去掉授权或出售**。<br>3. LinearMouse 和 Hidden Bar 是 **MIT**，可以自由借用。 | 闭源：只参考思路，自己从头写，MIT 的代码可以抄（保留版权声明）。<br>开源 GPL：可以直接借用 DockDoor、Ice 的实现，开发快很多。 | |
| D-03 | **自用还是发布？** | 决定是否需要多语言、新手引导、授权试用、自动更新、崩溃兼容等一大堆东西。 | 先按自用来做，架构上留好扩展的口子。 | |
| D-04 | **分发方式** | 需要全局事件监听（CGEventTap）、私有 API、不能沙盒，所以**上不了 Mac App Store**。 | 用 DMG + 公证（Notarize）+ Sparkle 自动更新，或者只自己编译使用。 | |
| D-05 | **你的硬件情况** | 刘海屏？外接显示器几台？鼠标型号（是不是罗技 MX）？用不用触控板？ | 你告诉我，我按情况调整下面「❓」项的优先级。 | |
| D-06 | **每个大模块能单独开关** | 用户可能只想要其中一部分功能。 | 🔴 P0：Dock 预览 / 窗口切换 / 鼠标 / 状态栏 四个模块各自独立开关。 | |

## 附录 B：技术要点与风险（给写代码时参考）

| 领域 | 关键做法 | 风险 |
|---|---|---|
| 权限 | **辅助功能**（必需，用于 AX 和 CGEventTap）；**录屏**（可选，用于缩略图）；日历和自动化按需申请 | 用户撤销权限后事件监听可能卡死输入，必须监听权限状态并主动释放 |
| Dock 悬停检测 | 对 `com.apple.dock` 进程做 AXObserver，监听选中项变化，得到当前悬停的图标；不用轮询 | macOS 大版本可能改 Dock 的无障碍结构 |
| 窗口列表 | 结合 CGWindowList、AXUIElement（每个 App 的 AXWindows），Space 信息用私有 CGS / SkyLight 接口 | 最小化的窗口截不到图，只能用缓存；Stage Manager 下有坑 |
| 缩略图 | ScreenCaptureKit（`SCScreenshotManager`、`SCStream` 实时预览）；把截图放进 XPC 子进程，规避 SkyLight 的内存泄漏（Thaw 的做法） | 系统会显示录屏指示器，用户会抱怨；开销大 |
| 鼠标事件 | HID 层的 CGEventTap 拦截按键和滚动；平滑滚动自己生成连续滚动事件 | 别的 App 也在用事件 tap 时会冲突 |
| 模拟触控板手势 | 往 CGEvent 里写私有字段，模拟 DockSwipe 和 Magnify 等手势（MMF 的做法） | **非常脆弱**：macOS 27 刚把它弄坏，MMF 3.1.0 才修好 |
| 指针加速 | 通过 IOHIDEventSystemClient 设置 HIDPointerAcceleration 等属性（LM 的做法），或者用 macOS 14 以上的系统开关 | — |
| 罗技 | 自己实现 HID++ 协议 | 工作量大，设备差异多 |
| 状态栏（macOS 26 及以下） | 用一个超宽的分隔 NSStatusItem（长度 10000）把左边的图标挤出屏幕；用合成的 ⌘ 拖动 CGEvent 移动图标；用 CGWindowList 列出图标窗口，再用 AX 的 `AXExtrasMenuBar` 匹配是哪个 App；用 `CGWindowListCreateImage` 截取图标图像 | macOS 26 上所有图标窗口都归控制中心所有，需要用 AX 反查 |
| 状态栏（macOS 27） | 主方案：私有的 `MBAssessmentModeAssertion`（考试模式白名单），实现按 App 隐藏。备选：长度略小于半屏宽的分隔符，把图标挤进系统的 « 溢出区。用 MenuBarAgent 的 AX 树列出所有图标 | 只能按 App 隐藏，不能用程序排序或点击；依赖私有 API，随时可能失效 |
| 图标间距 | `defaults -currentHost write -globalDomain NSStatusItemSpacing / NSStatusItemSelectionPadding` | 重新登录后才生效 |
| 分发 | 不用沙盒，DMG + 公证 + Sparkle | 上不了 App Store |
